| DL-004 | macOS integration | CGEventTap vs InputMethodKit vs hybrid | **CGEventTap, active HID tap, adapter written in Rust with raw FFI** (K-008 evidence: 16 extern functions + 1 extern static, 44 lines, no new crates, `CGEventKeyboardSetUnicodeString` round-trips Vietnamese byte-identically, no marked text per DL-017). The event mask is upstream's seven types — key-down, flags-changed, four mouse down/drag — because the language toggle (flags-changed) and the new-word reset (mouse) live outside key-down. InputMethodKit is rejected as the 1.0 mechanism because it forces the marked-text model upstream exists to avoid, and it changes behaviour, which parity forbids. Tap creation returns `NULL` until Accessibility is granted, measured on 2026-10-29; ad-hoc signing with the hardened runtime does not change that, so the denial is a grant and not an ABI fault. **Open verification, not an open decision:** one trusted run must print `RESULT=swallow-and-reemit-ok` before MAC-002 closes. If that run fails, the lane returns to this row rather than switching mechanism quietly.
